# Scratch Lens — 携帯対応スクラッチ検知Webアプリ

## 起動

Windowsでは `start_windows.bat` を実行し、PCのブラウザで http://localhost:8000 を開きます。Python 3が必要です。conda activateは不要です。
手動起動: `python serve.py`。index.htmlの直接ダブルクリックでは動きません。

## 携帯で使う

同じWi-Fi上の `http://PCのIPアドレス:8000` では画像アップロードは使用できますが、携帯のブラウザはHTTPのカメラ利用を許可しません。

カメラを使う場合は、このフォルダをそのままHTTPS対応の静的Webサーバーへ配置してください。ビルド不要です。全ファイルを同じ相対構成で配信してください（.wasmはapplication/wasm、.jsと.mjsはJavaScriptとして配信）。公開ホスティングはこの納品では行っていません。

社内LANで運用する場合は、携帯から信頼される証明書と秘密鍵を用意し、`python serve.py --port 8443 --cert server.crt --key server.key` で起動します。証明書のホスト名とアクセス先を一致させてください。信頼されない自己署名証明書では正常にカメラが動かない場合があります。秘密鍵は配信フォルダの外に置いてください。

対応想定: 現行Android Chrome / iOS Safari / PC Chrome・Edge。実機端末ごとの性能・互換性は要確認です。ブラウザのカメラ権限を許可してください。背面カメラを優先します。

## 操作

1. 新モデルまたは元モデルを選びます。
2. カメラを開始、または画像を選択します。
3. オレンジ色が傷の候補です。枠の番号は結果リストと対応します。
4. 枠内ラベルは領域内の平均予測確率です。右側に最大確率も表示します。
5. しきい値を調整できます。新モデルの既定値80%、元モデル50%。
6. 結果画像をPNGで保存できます。カメラ停止・画面離脱時はカメラを解放します。

新モデルは画像全体を長辺512/768/1280px以下に縮小します。既定768px。タイル分割はしません。小さな傷には1280pxを試してください。縮小で消失する傷や、元解像度での学習時との精度差があり得ます。
リアルタイム処理は1フレームずつ実行し、処理待ちフレームを蓄積しません。実際の更新頻度は端末と解像度に依存し、30fpsは保証しません。

## モデルと確率

- models/scratch_lite.onnx: 新しい軽量モデル。RGB float32 NCHW 0..1、出力は画素ごとの確率。
- models/one_ai_model.onnx: 元モデルの原本。そのまま保管しています。
- models/original_probability.onnx: 元モデルにSigmoidの確率出力を追加したファイル。アプリの「元モデル」はこちらを使用。重み・元の二値出力は変更していません。入力505×256、確率マップ252×128。
- models/manifest.json: ファイルサイズとSHA-256。

画素確率 > しきい値の8近傍連結領域を検出し、出力マップ上で3画素未満の領域を除外します。平均・最大確率は領域内の画素値から算出します。これは校正された信頼度や正解率ではなく、モデルの予測確率です。元・新モデルのパーセント値を同じ精度の指標として比較しないでください。

## 構成・プライバシー

HTML/CSS/JavaScript + ONNX Runtime Web 1.22.0 / WebAssembly CPU。推論はWeb Worker内で行います。ONNXとRuntimeは同梱済みでCDNアクセス不要、画像・映像はアップロード送信しません。初回はホストからアプリとモデルを取得します。オフラインキャッシュ機能はありません。
serve.pyはローカル検証用サーバーです。外部公開の本番サーバーにはHTTPS対応の静的ホスティングを使用してください。

公式資料: https://onnxruntime.ai/docs/tutorials/web/deploy.html
